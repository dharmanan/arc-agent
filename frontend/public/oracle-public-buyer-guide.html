Arc Oracle x402 Integration

Public Buyer Guide

Arc exposes paid Oracle endpoints over x402 using Circle Gateway as the settlement rail. You do not need an Arc account to buy these resources. You do need an EOA wallet, USDC on a supported chain, and an x402-compatible buyer flow.

What Arc Is

Arc is the seller. Your integration is the buyer. Public Oracle endpoints are ordinary HTTP routes until the server returns 402 Payment Required and the x402 payment flow begins.

What Arc Adds

Arc keeps Circle Gateway compatibility but adds a clearer onboarding layer, a public guide, a downloadable buyer example, and an auto-fund helper pattern for Gateway balance gaps.

Why It Is Easier

The raw Circle buyer flow leaves Gateway deposit timing to the integrator. Arc's helper pattern closes the common case where the wallet has USDC but Gateway available balance is still zero.

How The Flow Works

At the protocol level, Arc follows the same x402 pattern as Circle Gateway.

Step What happens
1. Unpaid request Call a public Oracle route such as /api/oracle/public/pool-state.
2. Seller challenge Arc returns 402 Payment Required, a JSON body, and a PAYMENT-REQUIRED header.
3. Buyer funding check Your buyer ensures Gateway available balance is sufficient for the requested price.
4. Signed retry Your buyer creates a payment payload and retries with a Payment-Signature header.
5. Settlement Arc settles through Circle Gateway and returns the Oracle response.
Arc vs raw Circle buyer flow: Circle's standard quickstart is protocol-correct but leaves funding orchestration to the buyer. Arc keeps the same wire protocol and improves the operational flow by advertising this guide and by using an on-demand Gateway funding pattern in its managed buyer helpers.
EOA only: buyer wallets must be EOAs. Smart contract accounts and EIP-1271 signatures are not supported by this nanopayment flow because Gateway verification is based on off-chain ecrecover.

Verified live Arc pair coverage: stablecoin-fx currently supports EURC/USDC and EURC/WUSDC with a live arcCurvePool snapshot in the paid response. pool-state currently maps USDC-EURC, EURC-USDC, EURC-WUSDC, WUSDC-EURC, WUSDC-USDC, and USDC-WUSDC. USDC-USYC remains mapped but the current Arc Curve pools are empty on-chain.
New Oracle SKU additions: peg-monitor returns spot stablecoin peg health with explicit fallback metadata, reserve-state returns Aave-style reserve APY state with fallback yield hints, protocol-tvl returns TVL and 24h change across the protocol watchlist, pool-compare compares multiple pool targets side by side across curve, uniswap_v2_like, and arcfx, and prediction-market-check returns a live Polymarket-based crypto regime snapshot with liquidity, movement, and Arc action guidance. arb-scan-multi scans several stable lanes at once and returns the strongest profitable lane.
Experimental paid pool-state coverage: QTM-WUSDC on uniswap_v2_like and MUSDC-MEURC on arcfx are available through the paid pool-state route.

Quick Start

Install the dependencies used by the public reference files:

npm install @circle-fin/x402-batching ethers
Tip: use your public Arc Oracle API base URL here. If you received a 402 challenge first, keep using the same seller base URL that returned the payment terms. During the testnet phase, the default public base URL is https://arcmachina.vercel.app/api.

Preview a live 402 response first:

ORACLE_PUBLIC_BASE_URL=https://your-public-arc-oracle-base-url \
ORACLE_PUBLIC_ENDPOINT=pool-state \
ORACLE_PUBLIC_POOL=USDC-EURC \
node oraclePublicBuyerExample.js --preview

Preview the EURC/WUSDC lane:

ORACLE_PUBLIC_BASE_URL=https://your-public-arc-oracle-base-url \
ORACLE_PUBLIC_ENDPOINT=stablecoin-fx \
ORACLE_PUBLIC_PAIR=EURC/WUSDC \
node oraclePublicBuyerExample.js --preview
ORACLE_PUBLIC_BASE_URL=https://your-public-arc-oracle-base-url \
ORACLE_PUBLIC_ENDPOINT=pool-state \
ORACLE_PUBLIC_POOL=EURC-WUSDC \
node oraclePublicBuyerExample.js --preview

Environment Variables

Variable Purpose
ORACLE_BUYER_PRIVATE_KEY EOA private key used for Gateway deposit and x402 signing.
ORACLE_PUBLIC_BASE_URL Arc backend base URL.
ORACLE_PUBLIC_ENDPOINT One of stablecoin-fx, pool-state, peg-monitor, reserve-state, protocol-tvl, pool-compare, prediction-market-check, yield-rank, arb-signal, arb-scan-multi.
ORACLE_BUYER_CHAIN Gateway chain name, defaults to arcTestnet.
ORACLE_BUYER_RPC_URL Optional RPC override for the selected chain.
ORACLE_BUYER_FUNDING_BUFFER_USDC Optional extra amount to deposit above the exact required payment.
ORACLE_PUBLIC_ASSETS Comma-separated asset list for peg-monitor or reserve-state.
ORACLE_PUBLIC_PROTOCOLS Comma-separated protocol list for protocol-tvl.
ORACLE_PUBLIC_TARGETS Comma-separated venue:pool list for pool-compare or arb-scan-multi.
ORACLE_PUBLIC_TOPIC Topic string for prediction-market-check, for example crypto or bitcoin.
ORACLE_PUBLIC_LIMIT Optional market sample size for prediction-market-check. Supported range is 1 to 8.

What The Helper Does

The downloadable helper wraps the highest-friction parts of the buyer flow:

  • Perform the unpaid preview request.
  • Parse the PAYMENT-REQUIRED header.
  • Check Gateway available balance.
  • Deposit on demand when Gateway balance is short.
  • Create a signed payment payload and retry the request.

Arc is not replacing Circle Gateway. It is packaging the same x402 settlement rail into a more discoverable and lower-friction integration surface for Oracle buyers.
